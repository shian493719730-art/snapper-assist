# 按原文选择 Skill

用户反馈 AI 完善过于模板化。旧路径先按关键词选择 recipe，并把预制草稿传给模型；新 AI 路径不再使用该草稿作为编辑依据。本地备用草稿仍保留在独立入口。

`RefinementSkills.routePrompt` 只提供原文、候选 Skill 元数据与已确认领域方法 ID，模型先按语义分析并选择，不能假称已经读取全部正文。`SkillPlan.parse` 校验实际存在的 Skill、数量、去重及理由。第二次调用由 `editingPrompt` 只提供所选完整正文和原文，保留本次否定约束，允许不采用无关方法，不规定统一输出结构。

指令来自本机普通 `.codex/skills/*/SKILL.md`、`.codex/skills/.system/*/SKILL.md`；不遍历符号链接，不运行 Skill 脚本，不执行用户原任务。随包的 17 种独立适配方法卡始终作为候选；通用推敲方法也不会因为存在本机 Skill 而被跳过。方法卡不是第三方脚本。CLI 仍采用隔离配置和只读编辑环境，保留原账号登录使用方式，不开启通用电脑或浏览器工具。新的高推理与两阶段调用仅在用户点击后发生。

本次修改路径：`SkillRouting.swift`、`SelectionAssistant.swift`、`PromptPreparation.swift`、`RefinementLaunch.swift`、随包方法与构建版本。原文、语气、已有事实、领域偏好、替换/撤回与取消保留。缓存按 Skill 内容变化失效。

本地检查实际验证路由只给元数据、编辑得到所选正文而非其他正文、伪造 Skill 被拒绝、内容指纹变化使缓存失效。生成由用户亲自发送；本轮未测真实模型质量。安装/候选包状态见 [0.9.0 候选记录](releases/v0.9.0-candidate.md)。

## 本轮编辑准则与证据边界（2026-11-19）

短而开放的请求需要相关的新信息，例如材料怎么用、哪些问题值得辨认、可选方向与取舍、下一步怎样开始。只做同义替换不满足这个目标。已经清楚或明确要求一句话的内容不强行扩写；未知时间、预算、材料与权限不补成事实，本次要求高于历史方法偏好。不规定“目标／步骤／交付／验收”的统一外壳。

加入三种人工编写的差异化示例：学习安排、页面整理和一句话改写。它们用于说明按任务取舍，不能作为模型实测成果。参考 OpenAI 的[提示工程指南](https://developers.openai.com/api/docs/guides/prompt-engineering)：分开指令、示例与参考上下文，使用覆盖不同输入的示例。将其用于本产品是设计选择，不是质量收益已经得到证实。

自动检查验证数据边界、已选正文和随包方法可用性；未发送真实模型请求，不声称已完成新旧输出盲评。质量验收可由用户分别点击“期末复习”“页面太乱，保留功能”“把这句改得口语一点，只给一句”，检查相关性、信息增量、事实保持与长度要求。
