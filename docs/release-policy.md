# Snapper Assist 更新与发布约定

用户长期要求，记录于 2026-11-10。后续默认执行，无需用户每次重复提醒；本次用户的具体指令优先。

1. **本地与 GitHub 内测包同步。** 对 Snapper Assist 进行已授权的功能、修复或随包方法数据更新时，同轮完成本地应用更新、同一 GitHub 仓库的内测包发布及相应下载说明。使用同一版本与构建产物，核对包内资源、签名及下载文件校验值；任一环节未完成，明确记录待同步，不能宣称两端均已更新。此约定不是操作系统级自动更新器，也不授权无关功能或其他项目的发布。
2. **保留偏好和数据。** 更新前备份现有应用、领域偏好、方法覆盖数据及应用设置，保留可回退路径。迁移只处理必要字段，保留用户的明确选择和无关本地修改；公共内测包只包含通用资源，不携带开发者个人偏好、账号凭据或私有业务数据。
3. **尽量减少辅助功能重复授权。** 保持 Bundle ID、安装路径和可用的签名身份稳定；可通过已有校验过的热加载路径交付的数据，不为本机数据刷新单独重建或重签应用。需要随内测包交付的资源仍须纳入同轮打包。不要反复重建、批量重置授权或扩大权限来试错。当前 ad-hoc 构建不能保证跨版本免重新授权；若 macOS 确实要求重新确认，仅恢复同一应用原有权限，系统密码或触控 ID 由用户自行完成。
4. **收费请求由用户发送。** Agent 不代用户发送收费模型请求；自动检查、演示和发布验收不启动收费生成。能够在本地完成的检查先完成，需要真实收费请求的部分准备好步骤，由用户亲自点击。
5. **按本轮范围验收。** 区分包检查、实际界面操作、用户反馈与模型质量比较，交付时说明实际完成和未验证的部分。用户要求停止或跳过测试时立即停止，不因安装完成而将未确认的功能标为通过。
6. **文档更新与软件更新分开。** 仅修改规范、说明或研究索引的文档工作不触发重建、重签、安装或内测包发布；涉及实际功能或随软件交付的方法数据新版时按以上同步约定执行。本次 2026-11-10 仅保存这些约定，不修改软件，不重新安装或发布版本。
