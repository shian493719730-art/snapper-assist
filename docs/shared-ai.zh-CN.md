# 共享 AI 与邀请码

0.10 内测版增加共享服务接入。朋友使用共享模式时无需安装 Codex、配置 API 或拿到维护者的模型密钥；在助手中输入邀请码即可连接。**本轮按维护者要求保持真实模型扣费关闭，邀请码可激活、查看状态，AI 生成尚未开放。** 本地草稿、替换和撤回仍可使用。

## 给朋友的步骤

1. 解压安装包，将正式的 Snapper Assist.app 移到固定的应用程序文件夹再打开。
2. 按应用引导在“系统设置 → 隐私与安全性 → 辅助功能”添加当前 App。返回助手点“重新检查”，以“已授权”的实际检测为准；不要为 Preview 授权。
3. 在授权页点击“共享 AI 与邀请码…”，也可从菜单栏 S 进入。保持默认共享模式，粘贴维护者单独提供的邀请码，点击“连接／保存选择”。
4. 看到“邀请码已连接 · 真实模型扣费未开启”表示连接成功。**这不是模型生成成功。** 目前先用浮条“⋯ → 使用本地草稿”，检查后替换，需要时撤回。
5. 以后获准开放额度后，点击 AI 完善才会请求模型：原文选方法，再按所选方法完善。未开放时会明确提示，不会自动转用本机 Codex。

邀请码每个绑定一台设备，有有效期，也可以被维护者撤销。换电脑或到期请联系维护者换码。模型密钥不需要也不能填到邀请码框里。本机邀请码保存在 macOS 钥匙串，设备 ID 保存在应用设置。

## 维护者与额度

共享服务：[Snapper Assist 共享 AI](https://snapper-assist-shared-ai.shian493719370.chatgpt.site)。公开地址不提供无认证生成；邀请码与管理凭证分开。管理页需要单独的维护者凭证。公共源码与安装包不含这些凭证或实际邀请码。

服务端同时检查：运行环境扣费开关、全局启用状态、总额度、个人额度、总次数、每日次数、有效期与撤销状态。当前运行环境开关关闭，全局和初始邀请码的金额/次数额度均为零。客户端不能提高额度或打开扣费。全局停用和邀请撤销在两次模型调用之间也会检查。

收费路径先用数据库的原子操作预留整次请求的保守费用，再开始模型调用；相同请求 ID 不重复执行。收到可信的使用量后结算并释放差额，网络失败或使用量不明时保留预留，避免重复调用或提前退款绕过上限。只有后续明确授权预算、核对所选模型单价并完成收费验收后，才能开放真实生成。应用内金额是按配置单价计算的本服务账目，不能替代供应商账单；供应商侧硬限额能力尚未验证。

`/admin/invites` 创建邀请码，`/admin/revoke` 撤销，`/admin/limits` 修改总额与个人限额；这些接口都需要维护者凭证，不会改变运行环境的扣费开关。`/admin/provider-check` 只读取模型目录，不发送生成。控制台创建的初始邀请码默认 7 天、零额度；运行凭证与邀请码仅留在维护者私有文件中。

## 数据与模型

点击 AI 完善后先检查共享状态；扣费关闭时不向生成接口发送选文。开放后，选文和已确认的领域方法偏好会发送到共享服务，再发送给维护者配置的 TideVerse。共享模式只使用服务端的 17 种公开方法，不扫描朋友的本地 Skill 文件，也不运行工具或原始选文任务。本机 Codex 作为单独的可选接入保留，需要用户明确选择。

服务不保存选文、建议正文或原始模型响应。账目保存请求哈希、时间、状态、使用量与额度；邀请码只存哈希。模型凭据在服务端加密保存，加密主密钥为独立的运行时 secret。模型供应商自己的数据政策仍适用。

## 验证边界

服务使用真实 SQLite 执行限额触发器，20 项本地服务测试覆盖禁用扣费、身份、设备绑定、到期/撤销、并发、预留/结算、重放与凭据加密。模拟模型完成过两阶段流程，不代表真实模型效果。线上邀请码连接、状态与扣费拦截另行记录；真实付费生成未执行，新电脑安装与跨软件兼容性仍待验收。
